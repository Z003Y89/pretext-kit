Headless parity

Each row is a UI label in English, German or French. The Node line was computed without a browser, by pretext-kit/headless (HarfBuzz shaping Inter and Roboto from test/fonts), and shipped as JSON. The here line is the same computation run live in this browser's Canvas, with the same font files loaded by @font-face. Each cell gives the line count and the widest line (measureLineStats) at that box width, and the largest size from 8px up to the label's own size that fits the box on one line (fitFontSize).

What this shows, and what it doesn't

  • Registered fonts only. The claim covers text whose every character is in a font you registered, the same files your CSS loads. A character none of them has throws HeadlessCoverageError in Node, where a browser would draw it from a system font no one can reproduce.
  • Chromium's rules. install() gives Pretext a Chrome user agent, so it breaks lines as Blink does. In Chromium every row should agree. WebKit and Firefox have their own line-breaking rules and text stacks, so rows may differ there; that is outside the claim, and this page shows it rather than hiding it.
  • macOS measured. Parity was measured on macOS Chromium (verify/HEADLESS_RESULTS.md: 4,992 widths, every Inter and Roboto one bit-exact; 71,818 line counts, none differing). Windows and Linux each still need their own measured check.
  • The Node numbers are regenerated by npm run examples:data (examples/build-headless-parity.ts); npm run examples:check fails if any row differs in Chromium and reports the counts in WebKit and Firefox.
