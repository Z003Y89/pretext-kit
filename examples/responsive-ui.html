pretext-kit examples

Responsive UI

One billing screen, laid out twice at the width you drag to. On the left (or top), pretext-kit chooses every font size, width and line count before anything paints. On the right (or below), the same screen with the fixed sizes a stylesheet would give it. Drag the width down, or switch to German, and watch where each one gives.

Inter, a web font, is still loading: until it arrives, both screens measure and paint the fallback, Helvetica Neue.

What each box uses

  • Toolbar: fitFontSizeRich sizes each icon and label as one row, 11–14px, on one line if any size allows, else two, else the button shows only its icon. CSS: 14px, nowrap, clipped.
  • Case row (icon, the chip 207/0011, a name): fitFontSizeRich with the chip as break: 'never'. CSS: 13px, one line, clipped.
  • Badge: fitFontSize, 9–12px in a box a third of the card wide. CSS: 12px, ellipsis.
  • Title: balance gives the narrowest width that keeps the line count, so there are no orphans, and the line count the card height needs. (CSS text-wrap: balance would fix the orphans too; it cannot give the height before painting.)
  • Body: clamp to three lines with an ellipsis measured in the body font; the card's height is known before it paints, so each row is as tall as its tallest card. CSS: -webkit-line-clamp: 3 in a card of fixed height.
  • Attachment: truncateMiddle keeps the date and extension. CSS: text-overflow: ellipsis keeps the start only.
  • Buttons: fitFontSize, 12–15px. CSS: 15px in a 40px-high button.
  • Fonts come from fontFromStyle(getComputedStyle(el)) on probe elements styled like each role; watchFonts clears Pretext's cache when Inter arrives, and the page prepares again.
